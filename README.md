# 🎓 קורס הבנת כלי ה-AI - LMS

מערכת למידה אינטראקטיבית (LMS) מקצה לקצה לניהול קורס הבנת כלי בינה מלאכותית, פרומפטינג והנדסת אנוש מולם. המערכת מאפשרת לסטודנטים ללמוד את סילבוס הקורס, לתרגל מבחנים אמריקאיים ולקבל ציון ומשוב אוטומטי מיידי.

🚀 **האתר באוויר באקליק:** [כניסה למערכת ה-LMS שלך](https://prompt-academy-lms.onrender.com)

---

## 🛠️ טכנולוגיות וארכיטקטורה

המערכת בנויה בארכיטקטורת Full-Stack מודרנית וקלילה:
* **Frontend (ממשק משתמש):** HTML5, JavaScript (Async/Fetch API) ועיצוב רספונסיבי בעזרת **Tailwind CSS**.
* **Backend (שרת):** **Node.js** יחד עם פרימוורק **Express** לניהול נתיבים (API Routes) וטיפול ב-CORS.
* **Database (מסד נתונים קבוע):** אינטגרציה מלאה עם **Google Sheets** דרך ה-API של SheetDB לשמירה קבועה של ציוני הסטודנטים בזמן אמת.
* **Cloud Hosting (אירוח בענן):** השרת והאתר מאורחים ומנוהלים על פלטפורמת **Render** (שרת אירופאי בפרנקפורט לביצועים מהירים).

### 📅 פרסום מודולים חדשים בהדרגה

למודול ב-`modulesDatabase` (בקובץ `server.js`) אפשר להוסיף שדה `availableFrom: 'YYYY-MM-DD'`:

* עד התאריך הזה המודול מופיע בסילבוס עם התווית **"בקרוב · תאריך"**, בלי התוכן ובלי המבחן. השרת גם מסרב לשלוח את המבחן או לקבל הגשה עבורו.
* בחצות של התאריך (שעון ישראל) המודול נפתח אוטומטית, בלי צורך לפרסם גרסה חדשה.
* חשבונות ב-`OWNER_EMAILS` רואים אותו מראש (תווית "תצוגה מקדימה") כדי לבדוק אותו לפני כולם. זה עובד רק כשההתחברות עם Google פעילה (כלומר `PAYWALL=on` עם כל ההגדרות).
* מודול חדש צריך גם מבחן ב-`quiz.js` ותוכן נוסף ב-`moduleExtras.js`. הבדיקות האוטומטיות (`npm test`) מוודאות שלכל מודול יש את שניהם.

## 📝 מבחני ההסמכה

* לכל מודול 4 שאלות אמריקאיות עם 4 אפשרויות, וציון מעבר של 75.
* מאגר השאלות, התשובות וההסברים נמצא בקובץ `quiz.js` בצד השרת בלבד. הדפדפן מקבל את השאלות **בלי** התשובות (`GET /api/modules/:num/quiz`), והבדיקה נעשית בשרת (`POST /api/submissions`).
* סדר האפשרויות מעורבב בכל טעינה, ואחרי ההגשה מוצג לכל שאלה הסבר קצר.
* ההתקדמות האישית (אילו מודולים עברו והציון הגבוה ביותר) נשמרת ב-`localStorage` של הדפדפן בלבד.

## 📊 מבנה מסד הנתונים (Google Sheets)

אם הוגדר `SHEETDB_URL`, כל הגשה נרשמת בגיליון עם העמודות הבאות:
1. `id` - מזהה ייחודי להגשה (Timestamp).
2. `שם` - שם הסטודנט כפי שהוזן.
3. `מספר מודל` - מספר המודול.
4. `שאלה` - כמה תשובות נכונות מתוך כמה (למשל `3/4 נכונות`).
5. `תשובה` - התשובות שנבחרו (JSON).
6. `feedback` - ✅/❌ לכל שאלה.
7. `ציון` - הציון הסופי (0-100), מחושב בשרת.

## 💻 הרצה מקומית על המחשב (Local Development)

1. ודאו שמותקן [Node.js](https://nodejs.org/) בגרסה 18 ומעלה.
2. התקינו את הספריות:
   ```bash
   npm install
   ```
3. העתיקו את `.env.example` ל-`.env` ומלאו את הערכים (`SHEETDB_URL` אופציונלי - בלעדיו הציונים נבדקים אך לא נשמרים בגיליון).
4. הפעילו את השרת:
   ```bash
   npm start
   ```
   והיכנסו ל-`http://localhost:5000`.
5. הרצת הבדיקות האוטומטיות:
   ```bash
   npm test
   ```

## 🔒 חומת תשלום והתחברות עם Google

* `FREE_MODULES` המודולים הראשונים פתוחים לכולם. השאר פתוחים רק למי שמחובר עם חשבון Google **שנמצא ברשימת הרוכשים**.
* **רשימת הרוכשים** היא לשונית בשם `buyers` באותו גיליון Google Sheets, עם העמודות `email`, `code`, `date`. כל שורה עם אימייל = גישה מלאה לחשבון הזה. אפשר להוסיף שורות ידנית בגיליון.
* **קוד גישה חד-פעמי:** קונה מחובר מזין קוד מ-`ACCESS_CODES`, והשרת מוסיף שורה ללשונית `buyers`. מאותו רגע הקוד קשור לחשבון הזה ולא יעבוד לחשבון אחר.
* התוכן של מודול נעול (שיעור, מקרי בוחן, תרגול ומבחן) **לא נשלח לדפדפן בכלל**.
* ההתחברות מאומתת בשרת עם הספרייה הרשמית של Google (`google-auth-library`), והסשן נשמר בעוגייה חתומה (`HttpOnly`, `SameSite=Lax`, `Secure` ב-HTTPS) לתקופה של 30 יום.
* יצירת קודים: `npm run codes -- 20`

### הגדרת Google Sign-In (פעם אחת)
1. ב-[Google Cloud Console](https://console.cloud.google.com/apis/credentials) יוצרים **OAuth client ID** מסוג **Web application**.
2. ב-**Authorized JavaScript origins** מוסיפים את כתובת האתר (למשל `https://prompt-academy-lms.onrender.com`) ולפיתוח מקומי גם `http://localhost:5000` ו-`http://localhost`.
3. מעתיקים את ה-Client ID למשתנה `GOOGLE_CLIENT_ID` ב-Render.

## 💳 פתיחה אוטומטית אחרי תשלום (Grow)

1. הקונה מתחבר עם Google, לוחץ "לרכישה" (`CHECKOUT_URL`) ומשלם בדף של Grow. במסך מוצג לו באיזה אימייל להשתמש.
2. Grow שולחת הודעה (Webhook) לכתובת `https://<האתר>/api/webhooks/grow/<GROW_WEBHOOK_SECRET>`.
3. השרת בודק שהתשלום אושר ושהסכום לא נמוך מ-`COURSE_PRICE`, ומוסיף את האימייל ללשונית `buyers` (בעמודה `code` נרשם `GROW-<מספר עסקה>`). הודעה כפולה לא יוצרת שורה נוספת.
4. הקונה לוחץ "כבר שילמתי" והקורס נפתח.

* את ה-Webhook מפעילים דרך התמיכה של Grow (לפי התיעוד שלהם), ונותנים להם את הכתובת מסעיף 2.
* אם בדף התשלום יש שדה מותאם עם אימייל (למשל "אימייל של חשבון Google"), גם הוא מקבל גישה.
* קודי הגישה (`ACCESS_CODES`) ממשיכים לעבוד כגיבוי למכירה ידנית.
